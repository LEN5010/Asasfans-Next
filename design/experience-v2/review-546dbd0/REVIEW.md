## 结论

保留 A「内容刊」作为下一轮基础，不重新启动全站设计选型。这轮已有真实的页面结构改造和可重复的截图实验台，不能再评价为仅换色或改圆角。但它仍不是可宣布完成的体验版本：有未覆盖的跨应用返回路径、长查询布局问题、过度统一的媒体裁剪、尚未完成的 U18/U20，以及候选分支缺少 CI、安装包和设备证据。

`PARTIAL_BLOCKED` 是合理的最终状态；但它不意味着全部剩余工作都必须等待手机。功能修复、状态页、动效逻辑、图片预览策略及 headless 布局测试可以继续做。

这是独立静态与提供图片的复审，不是独立运行验收：本次没有执行 Flutter/analyze/test/build，没有操作真实手机，没有读取生产数据，没有修改或推送仓库、开 PR 或触发 CI。856 测试来自仓库提交的本地运行记录，不是本次重新跑出的结果。只检查了提供的七屏总览及关键实现，不声称逐张验收了仓库全部原型、深色和压力截图。

## 二、优先修复的发现

### F01｜高优先级：普通二创详情外跳丢失原浏览上下文

**证据等级：静态调用链确认。未在本次真机复现。该链路是本轮保留下来的旧缺口，不将它说成已证明的新引入回归。**

位置：
- `lib/features/content/presentation/content_page.dart`：`_FanartGrid` 调用 `openFanart`，传入频道、已提交 query、内容 identity 和 offset。
- `lib/features/content/presentation/fanart_detail_page.dart`：`openFanart` 只在视频直接外跳分支继续传入这些信息；图片/文本进入 `FanartDetailPage(item: item)` 后丢掉它们。
- 同文件 AppPageBar 的“打开原动态”仅向 `openContentSource` 传 item/url。
- `lib/features/library/presentation/library_common.dart`：缺省 `returnTo` 被转换为 `ReturnTarget.today`，非 contentChannel 时 channel 被清空。
- `lib/features/handoff/presentation/return_restorer.dart`：today 目标导航至 `/today`。
- `HandoffCoordinator.open` 只有 contentChannel 且 channel 非空才更新 BrowseSnapshot。

用户路径：二创选嘉然和类别 → 打开图片作品 → 详情点原动态 → 去 B 站 → 应用进程被回收 → 返回。持久化上下文不是原二创查询；“继续挑选”也不会正确记录这次详情外跳。热回页面仍在，可能掩盖问题。

修复：为详情显式携带可选 origin/returnContext，所有二次外跳复用该上下文。详情来自今日、收藏或其他合法入口时保留真实来源，不能全部强行写成二创频道。统一审查来源按钮和更多动作中的外跳入口。补正常图片、文字、多图详情路径的测试，而不只测视频 tile 直接外跳。

### F02｜高优先级：查询摘要只有短标签测试，长查询存在溢出路径

**证据等级：布局约束推导，高置信；本次未执行触发用例。**

`lib/shared/widgets/query_summary.dart` 用 `Wrap` 包裹所有条件按钮，但按钮内部是 `Row(mainAxisSize: min, children: [Text(label), ..., Icon])`，文字没有 Flexible、最大宽度、maxLines 或 ellipsis。二创的 `label` 直接使用整个 keyword。Wrap 能换整颗按钮，不能替内部 Row 的非 flex 文本施加正确的可用宽度。Flutter Row 官方布局算法也说明非 flex 子项先接收不受限的横向约束。

`test/shared/query_summary_test.dart` 测试最热、一周内、秋天等短词，没有长中文/无断点字符串和窄屏大字组合。

修复：给单项摘要明确宽度和文本策略，视觉可截断但完整语义/筛选面板保留原值；摘要默认显示主要1–2项和剩余数量，而不是把全部条件无限换行。必须检查 320/390 宽、1×/2×字号、长中文与长无断点文本，清空和单项移除仍可操作。

额外语义问题：FanartFilterBar 的“清空”保留 members，只清该摘要层的条件。这个作用域可以成立，但通用“清空/重置筛选”容易误解。选择“清除更多条件”或增加明确的“清除全部”，并让真实结果、tooltip 与测试保持一致。

### F03｜中高优先级：4:5 不应成为所有媒体的硬性模板

**证据等级：代码明确；裁剪比例为几何计算，不是手机测量。**

`FanartCard` 对图片和视频都使用 `artworkRatio=4/5`、`BoxFit.cover`、`Alignment.topCenter`。对于横向16:9封面，铺满4:5区域后可见宽度只有原图的 `(4/5)/(16/9)=45%`，即左右合计约55%被裁去。装饰图片看不出问题，带标题、字幕、画面两侧人物或多格漫画的封面更容易丢信息。

不能只把 `aspectRatio` 改成按类型选择就结束：`_FanartGrid` 的固定 mainAxisExtent 来自首项 `FanartCard.extentFor`，当前函数忽略 item，是因为所有类型恰好等高。类型分化后要同步修改布局与几何计算，补新高度下的返回锚点测试。

另外，图片策略仍只接受展示宽度和 DPR，没有接收目标高度/BoxFit。横图被放大铺满竖向盒子时，按盒宽缩小的解码图可能再次放大而显糊。解决预览裁剪与解码需求应同步，不靠把全局图片预算调大。

建议：视频保留16:9；图片有可靠尺寸时用有限比例模板或现有惰性布局，无尺寸时稳定预览；文字使用阅读单元。不要为探尺寸批量下载原图，也不要重新加入所有类型共用的厚外框。

### F04｜中优先级：作品详情首图无限高会把作者与正文推到很远

**证据等级：结构与比例推导。**

详情现在把第一张图放在 author/text 之前，而 `_DetailImage` 按完整比例 fitWidth，没有首屏预览高度上限。1000×30000 的长图按358逻辑像素宽呈现，其显示高度约10740逻辑像素；总像素解码预算不会改变这个纵横比。详情可能需要滚过很长图后才看到作者与正文。

建议首图区域有视口相关的预览上限，作者/来源以紧凑方式可发现，提供明确“查看完整图片/长图”的入口。原查看器继续提供完整 fitWidth、缩放与多图能力，不能静默裁掉正文又不给完整入口。未知尺寸也应有稳定的临时布局；不要额外下载整张大图只为决定布局。

### F05｜待验证风险：继续挑选按三帧清理，不是可靠消费协议

**证据等级：风险审查，未证明正常操作中已发生。不能作为已复现线上事故报告。**

`ContinueBrowsingRow.onTap` 调用 resumeBrowsing、go(route)，等待三次 endOfFrame 后无条件 dropBrowseRestore。后者不校验请求编号。三帧既不能证明目标 feed 已消费，也不能保证旧清理不会影响更新请求。异步 `_restoreReturn` 在 await 查询/分页后也应确认请求仍有效，不能继续修改用户新选择的列表位置。

用最小的 requestId + 单次 claim/ack/cancel 替代帧数约定，复用已有 generation。无需事件总线或通用会话框架。优先补延迟挂载、切换到其他频道、用户新提交查询、连续恢复的受控测试；若风险未触发，也不要宣称修复了已发生的故障。

内存快照本身是可接受的范围收敛：它不是跨次启动的最近浏览，也不是 B 站播放进度。是否加入过期/持久化是产品决定，不能在修复期间无理由扩张数据库。

### F06｜中优先级：无溢出不等于触控、大字与信息可读性达标

- CreatorLink 是无最小尺寸的 InkWell，卡片作者行可能仅12字号、约16.2逻辑像素高。这是已知旧模式，应该现在解决。
- `VideoCard` 元信息为11字号，包含完整日期，并为右侧更多按钮保留宽度。截图里日期被截断；不宜继续缩字号来提高密度。
- Today 的 VideoRow 封面固定136宽，加12间距和48更多按钮后，320宽窗口扣除边距仅剩约92宽标题区域。大字时即使不抛异常，仍可能很难读。
- Mine 的 tile label 单行省略且列数至少2；窄屏大字下完整入口名称容易丢失，应允许两行或进一步减列。
- 日历默认日期高度44，320宽下7列每列约43.4。不能给七格各画一个重叠48热区来假装通过；提供可达的大目标日期选择/议程替代路径，并明确例外。

建议移动端关键操作以48逻辑像素热区为目标，视觉尺寸与触摸区域分离；桌面触屏与鼠标输入分别检查。作者头像+作者名可组成一个完整可点区域，不能让扩大的热区抢走作品点击或相邻更多按钮。

### F07｜证据改进：现有截图套件主要是捕获与布局烟测

`current_pages_test.dart` 明确写了普通 flutter test 只检查 scene 能构建而不抛异常；`shoot` 写 PNG/JSON，并不自动比较批准基线。因此“截图实验台完成”是真的，“像素回归已全部通过”则不是当前机制自动证明的。

`_loadFonts` 还将同一 CJK 字体注册为 Roboto、serif、sans-serif、monospace。这个决定便于可读的结构验证，但小说“衬线”效果及真实 Android/iOS fallback 不能据此验收。

图片都是自绘渐变、圆点和山形，适合确定性测试，却难以暴露裁掉字、人物位置和复杂背景上的可读性问题。加入带边缘标签、中心/边缘内容、全白/全黑和长图多格内容的诊断 fixture；有许可的真实复杂素材可以仅作为独立视觉走查输入，不必引入正式包。

少量已认可核心画面可增加受控 golden 或布局几何断言；不生成数千张图、不自动覆盖全部基线。记录字体、fixture版本、代码版本、是否脏工作区、安全区和 renderer；不分发系统字体。

## 三、对七屏图的设计意见

这是设计建议，不伪装成用户研究结论。图中是缩小拼图且素材为测试内容，不能据它断定真机字体、真实玻璃或性能。

| 页面 | 保留 | 下一步收口 |
|---|---|---|
| 今日 | 日期身份、安静的议程、作品与视频不同呈现、历史后置 | 议程/作品之间减少机械等量留白；窄屏 VideoRow 更灵活；继续挑选保持轻量，不做永久播放器 |
| 二创 | 文字频道 tab、只保留一排成员、去厚边框 | 按媒体类型预览，长图完整入口，条件多时仍紧凑；作者可点范围扩大 |
| 视频 | 原生16:9内容、紧凑网格、没有假搜索框 | 标题优先；日期采用短格式并保留完整语义；作者与更多操作不挤掉正文 |
| 动态 | 单列阅读、正文与转发区别 | 统一引用留白与元信息；长文/多图/展开后返回的稳定性；不加玻璃卡片 |
| 小说 | 作品书目式列表、正文安静 | 真实平台字体检查；受限作品和来源保持；reader 可复用但需明确验收 |
| 日历 | 日期条+议程、取消改期用文字 | 月份、日期、类型、成员、日/周、日期标题过多层；保留日期导航，合并次级筛选，减少默认控件堆叠 |
| 我的 | 内容与设置分离、最近浏览按实际数据出现 | 收藏/稍后看优先，其余不要全等权；设置可加根标题旁入口；大字完整标签；不造账号中心 |

底部浮栏覆盖滚动中的一部分内容并不自动构成 bug。要验收的是最后一个条目、关闭按钮、键盘、系统手势区是否仍可达。Solid 图片不能用来判定真实玻璃“完全没有”或“光学通过”。

## 四、U20 应完成什么

Liquid Glass 应加强控制与内容的关系，不是扩大模糊面积。保留现有玻璃依赖和有效档策略，不默认高档，不迁移全套框架。

1. 导航：保留已有选中与按压反馈，只修明确的位移、选中态和可读性问题。
2. 筛选：入口、面板、提交后摘要之间有可理解的连续性；复杂条件用稳定面板，不强制扭曲成一个巨大透明气泡。关闭后焦点回到入口。
3. 作品详情：图片与原列表的关系可见，退出回到原 identity；视频仍直接外跳，不能为了动画新建播放详情页。
4. 收藏/稍后看：局部状态与存储结果一致，失败不展示成功；可用短动效或语义反馈，不需要飞越全屏的装饰。

先在 Solid 完成行为和几何；再在原有 Regular/Premium 上验证材料。整个应用已有页面过渡，缺的是这几条专门设计的关系。减少动态/高对比/减少透明度各自尊重。不要在整块折射玻璃外简单套不透明层隔离背景；不要 await shader 初始化阻塞首帧。

## 五、继续开发顺序

详细任务见 FOLLOWUP_TASKS.md。先完成 F01、F02 这类真实链路与布局问题；为媒体建立能暴露裁剪的 fixture；随后做媒体/触控收口、U18/U20，再补候选 CI 和设备。

不重新搜一大批应用、不再做第三轮三方向竞赛、不更换路由状态管理、不重建数据库、不添加播放器/云账号/推送系统、不为凑额度改 SDK 或堆测试框架。

## 六、构建与最终交付

未替用户执行远程操作。建议用户批准后：
- Flutter Checks 选择候选分支，明确 `run_tests: true`。
- Flutter Development Validation 构建候选的既有四平台目标。
- Flutter Performance Validation 为独立 perf 身份生成 Release/Profile 和各 ABI 产物；使用现有明确批准的测试签名选项。
- 本轮 UI 的 AOT 对比基线为7134a40，候选为最终修复提交。Debug→Release 构建收益和本轮代码收益分开。

最终报告需说明：本地执行记录、CI运行、产物hash、安装、系统输入、光学、性能各自状态。没有设备不能写流畅提升百分比。

FINAL.md 的“除一个提交之外回退顺序无关”不够稳妥：新页面、token、组件和测试存在依赖。应给一致的阶段回退范围，按逆依赖顺序撤销，或在干净 worktree 验证整组回退。没有 schema 变化不代表任意单提交回退都可编译。
