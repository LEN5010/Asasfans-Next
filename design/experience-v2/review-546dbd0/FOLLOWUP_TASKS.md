# Experience V2.1 · 有界收口任务

不是重开设计项目。保留 A「内容刊」、四主导航和这轮已经建立的真实截图实验台。以下任务全部为本次建议，未在本次会话实施。

## 完成口径

每项分别登记：实现与代码测试、真实 widget 布局、内部设计复核、设备验证。没有做的项目保留 pending；设备缺席不阻止独立的代码与布局工作继续，也不能替未做页面找理由。用户审美批准单独保留 pending。

## R01｜补齐普通二创详情的来源与返回上下文

优先级：高。前置：无。

范围：`fanart_detail_page.dart`、`content_page.dart`、`library_common.dart`、必要的来源动作入口、`test/handoff/`。

实施：
1. 先写从带条件二创列表打开图片/文字详情、再点原帖的失败测试，检查发送给 handoff 的 target/channel/query/anchor。
2. 给详情添加显式可选 origin，贯穿来源按钮和更多动作；不是所有详情都来自二创，今日/资料库来源正确保留。
3. 不修改外链白名单、不新增播放器或后台 Flutter engine。

验收：图片、文本、多图、视频直接外跳各一条路径；模拟持久化后冷恢复，回到承诺的频道/查询/可恢复目标；恢复不能自动外跳。存储失败提示和普通热回保持。

交付：修复前 failing test、修复后结果、路径矩阵。真机仍可单独 pending。

## R02｜限制摘要布局并统一清空语义

优先级：高。前置：无。

范围：`query_summary.dart`、四频道摘要调用点、`fanart_filter_bar.dart`、`test/shared/query_summary_test.dart`。

实施：
1. 为长文字按钮提供有限宽度、Flexible 或其他明确布局约束、单行/省略策略；完整值保留在语义与面板中。
2. 默认展示主要1–2项加“另N项/全部条件”入口；不把所有条件自动展开成许多行。
3. 明确成员快捷选择与摘要清空的范围。通用“清空”若不包含成员则改名，或提供真正全清。
4. 条件动画不能让用户新查询被旧滚动恢复覆盖。

验收：320/390宽 × 1/2倍字号；至少40字中文、120字符无断点文本、六个条件、空摘要；没有RenderFlex溢出；单项删除与全部清除后结果完全一致；按钮和筛选仍能用。

## R03｜让媒体类型决定预览，并同步解码与布局

优先级：高。前置：R08先完成诊断fixture部分。

范围：`fanart_card.dart`、`content_page.dart` 网格、`media_cover.dart`、`media_image_policy.dart`、`fanart_detail_page.dart`、媒体与返回测试。

实施：
1. 视频封面保留16:9，图片根据可靠元数据或稳定模板呈现；不能一律4:5 cover。
2. 同步检查 extentFor、SliverGrid 主轴高度、文字单元与宽屏。不要仅改一个 aspectRatio 后仍用第一项高度代表全部类型。
3. 预览策略考虑展示高宽/BoxFit，维持原始URI与预览URI分离及总像素预算；无尺寸不得批量下载大原图探测。
4. 首张长图的详情预览有视口相关上限，作者和来源可发现；完整长图在现有viewer可读、可缩放，不能静默缩成不可读。

验收：横图、竖图、超长图、视频封面、文本、多图/GIF的类型矩阵；边缘文字与中心目标诊断图；返回第30项在新高度下可见；没有增加第二套图像/玻璃框架。未知源比例的解码取舍明确记录。

## R04｜把继续挑选从帧数约定改为单次请求协议

优先级：中，先用测试验证风险。前置：R01。

范围：`continue_browsing.dart`、`handoff_coordinator.dart`、各feed的_restoreReturn、相关tests。

实施：
1. 给一次恢复产生不可混淆的requestId，只能由对应目标claim/ack或对应取消清理。
2. 删除不带请求校验的“三帧后全清”；未挂载/离开目标的取消由明确导航生命周期处理，必要超时仅是后备。
3. await 查询和分页后确认当前请求/generation仍有效；用户新筛选与主动操作优先。
4. 保留单个内存snapshot与一次性持久ReturnContext分离。不因本任务加入跨设备同步或无限会话历史。

验收：延迟挂载、目标未找到、连续恢复、主动换条件/换频道、snapshot关闭和清历史。旧请求不得清除或滚动新请求。未复现的风险如实记录，不伪造线上故障。

## R05｜逐页视觉与触控收口

优先级：中。前置：R02、R03和R08的fixtures。

范围：`video_card.dart`、`creator_link.dart`、`mine_page.dart`、`calendar_page.dart`、`channel_tabs.dart`、必要theme/token。

实施：
1. 作者头像和署名组合成明确热区，和卡片/更多动作不重叠；正常小控件按48逻辑像素热区目标检查。
2. VideoCard 元信息保留一层必要信息；完整日期改紧凑显示但完整语义可达。Today VideoRow 在窄宽/大字下减少固定封面宽度，不能仅缩字号。
3. 我的页突出收藏和稍后看，设置可放标题旁；单行标签遇大字允许换行或减列，旧入口保持。
4. 日历默认保留日期与议程，把低频类型/成员控制合并为可展开区域；不删除日/周/月和筛选能力。
5. 320宽七日格不伪造重叠48热区；提供可用的大目标日期/议程替代入口。频道tab补适合的组/标题与选中语义。
6. 只调节确有问题的留白、层级与控件，不换整套设计方向。

验收：390默认和320大字逐页图；鼠标/键盘焦点检查；输入面板与安全区模拟；“我的内容”入口名称、视频标题和日程长标题可理解。真实TalkBack/系统字体仍待设备。

## R06｜完成 U18：工具、更新、空错与分页状态

优先级：中。前置：R02。

范围：`tools_sheet.dart`、updates presentation、`feed_scroll_view.dart`、`feed_status_footer.dart`、库资料异步状态。

实施：
1. 复用现有工具用途分组，统一标题、说明、失败与关闭后焦点；已经分组不能算新成果。
2. 更新页只展示真实的改期/取消/其他已有记录，不能暗示全天候实时推送。
3. 首次加载、首次失败、正常空、筛选无结果、规则全隐藏、旧缓存、尾部失败要有不同信息及下一步。
4. 刷新和尾部重试不抹掉旧内容；不另造通用状态平台。

验收：每种状态至少一个fixture；外链失败可恢复；重试不重复条目；旧内容不白闪；关闭面板焦点回入口。

## R07｜完成 U20：必要交互，而非堆特效

优先级：中。前置：R01–R03、R05、R06。

范围：现有app_motion/panel/glass与详情、内容动作调用点。

实施：
1. 明确已存在的导航/按压/默认路由过渡，先保留，不重复算新增。
2. 筛选入口→稳定面板→结果摘要的连续关系；退出焦点恢复。
3. 作品详情进入/退出与列表identity相连。大图缩放与滚动不能被手势截获，视频继续直接去B站。
4. 收藏/稍后看有和持久化成功一致的局部状态反馈；失败不先显示成功，系统减少动态仍能读到结果。
5. 保持原来单玻璃依赖和有效档。Solid零背景采样，高档只放功能层；不逐卡玻璃，不阻塞首帧，不换整个router。

验收：实际交互阶段截图/测试；动画结束后几何和状态正确；减少动态同功能；真实shader/耗时标注待设备，不拿Solid图替代。

## R08｜补足视觉证据的盲区（前置部分尽早做）

优先级：高。前置：无。

范围：`test/visual/`、少量高风险widget tests、visual_capture工具和manifest。

实施：
1. 保留现有确定性渐变fixture；补边缘文本、不同纵横比、全白/全黑、长图分格和长查询等诊断输入。
2. 为少量核心页面添加批准基线的golden或几何断言；不能把“成功写PNG”当“与基线一致”。禁止自动一键接受所有新图。
3. 原始1:1截图与总览同时保留，分开代码/fixture/字体/安全区/renderer因素；同一CJK注册多个字体族的局限如实标记。
4. 加至少一个带顶部安全区、底部手势区和键盘的场景。诊断素材小体积，不进正式assets，不打包系统字体。

验收：故意制造已选核心页面回归时测试确实失败；缺字体/未输出图不可记布局验收通过；两次固定输入可复现。

## R09｜候选构建、设备与最终交付

优先级：发布前必须。前置：代码部分完成后执行；设备部分独立等待。

范围：已有workflows、APK报告、tests和最终报告。

实施：
1. 未获授权不触发CI。获准后在候选分支运行Flutter Checks并显式run_tests=true；不要使用main旧记录。
2. 四平台已有开发构建分别登记；Android隔离perf身份Release/Profile、arm64/armv7，检查manifest、签名、ABI和Debug资源缺失。
3. 本轮UI用7134a40与最终候选同ABI/mode构建比较；D0 Debug与Release减包收益另列。
4. 真机至少目标老机和普通机，固定数据/缓存/刷新率/renderer，测滚动、图片、前后台、筛选和B站返回。无设备不编数字。
5. 按实际依赖给阶段级回退指令；不承诺任意一个提交都能单独无序revert。

验收：本地日志、CI runs、产物hash、截图与原始trace分别对应确切SHA；未做事项不涂绿。只剩设备时才用ENGINEERING_AND_LAYOUT_VERIFIED_DEVICE_PENDING；仍有页面/代码/构建缺口则PARTIAL_BLOCKED。

## 运行顺序与停止边界

建议 R01、R02、R08基础 → R03、R04、R05 → R06、R07 → R08核心回归收口 → R09。

单主agent写代码，最多一名只读审阅者即可；无需新建大型协作框架。每包一个可解释提交和针对性测试，受影响范围通过后阶段性全测。最终留出收尾容量；缺手机只停止手机依赖项，不停止U18/U20。功能/预算/权限遇真实阻塞时记录准确原因，不按“额度已经花完”宣称目标完成。
